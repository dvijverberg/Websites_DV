02 — Packaging · software · automation

From a customer request to a proposal, automatically

At Click-Pax I design packaging concepts for clients. Lately most of my time goes into the tools around that work: a chain of programs that turns a request into a dieline, a print, 3D renders, a price indication and a proposal.

The chain

01
Request → proposal

Every quote needs the same steps: a dieline, a print mock-up, renders, a price and a document. I built that route as a chain of small programs. Each block has a fixed input, its own tests and a contract with the next one, so a block can be improved without breaking the rest.

No language model does the maths. The calculations are deterministic and traceable; a person checks the result before it goes out.

    Folding boxes in Blender

    03
    Add-ons · Python

    The render step runs on a Blender add-on that reads a flat dieline, folds it into a real box with layered flaps, bend radius and board thickness, puts the print on it and renders fixed views in kraft, brown or white board. It runs headless, so renders can be made in the background or on a server.

    A colleague built the base version. I added folding recipes for autolock bottoms and full-flap boxes, the correct closing of mailer boxes, board colour and print options in the render plan, and a fix for renders that came out too dark. I also built a second add-on from scratch that lays paper insulation liners into a box procedurally with Geometry Nodes.

    Fig. 3 — Rendered by the add-on from a script: one DXF and two print PNGs in, finished views out. The print is my own concept.

    • 01 · Read

      Imports the ArtiosCAD DXF. Cut lines become panel edges, crease lines become hinges.

    • 02 · Fold

      A recipe per box type says which panel folds when, how far and on which layer.

    • 03 · Board

      Real board thickness, layered flaps and a bend radius. Flaps never run through each other.

    • 04 · Print

      Separate artwork for the outside and the inside, placed 1:1 on the dieline.

    • 05 · Views

      Fixed views, closed and open, on white and transparent. Kraft, brown or white board.

    • 06 · Headless

      Runs without the interface from a queue, in the background or on a server.

    Second add-on · built from scratch

    Climaliner

    Paper insulation liners for chilled and frozen shipments, laid into any box procedurally. Select the box, click, and a U-liner appears that fits its inside dimensions; add a second one crosswise inside it.

    The liner is generated with Geometry Nodes: paper and core as separate materials, fold radius, glue edge, wrinkles and small imperfections, each liner with its own seed.

    Fig. 7 — A U-liner and a cross liner in a plain FEFCO 0201, rendered with both add-ons from one script.

    Packaging concepts

    04
    Design work

    The design side is where it started: packaging concepts for clients in horticulture, from first sketch to production-ready design, with direct client contact.

    For sister label Iso-PAX I made concept proposals for webshops that ship frozen or chilled meat: their own print on our box, renders with the insulation liners inside, test data and box types, in a three-page PDF per company.

    How I work with AI

    05

    • AI as a development partner

      I build these tools together with Claude. It lets me build software well beyond what I could write alone, as long as there is discipline around it.

    • Tests, contracts, reviews

      Every block has tests. Changes go through a branch and a pull request with green tests in a shared repository. Fields may be added, never renamed.

    • Never invent data

      Unknown values are marked for checking instead of guessed. A proposal with open checks gets a draft watermark and can't be finalised.

    • People stay in the loop

      The chain does the repetitive work; a person checks the output, and anything the tools reject goes to a human.
